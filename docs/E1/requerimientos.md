## 1. Cómo se escribió y cómo se revisó cada requerimiento
| Característica | Cómo se aplica aquí |
|---|---|
| **Necesario** | Cada requerimiento remite a un objetivo de calidad de E0 (O1 a O3), a un criterio de la rúbrica de E1 o a una decisión del [contrato de datos](contrato_datos.md). Los que son **nuevos** (no venían de E0) se marcan **PROPUESTO**. |
| **No ambiguo** | El criterio de aceptación es una cifra, un umbral o una condición que se cumple o no se cumple; no usa «rápido», «seguro» ni «adecuado». |
| **Verificable** | Cada uno indica el método (prueba automatizada, inspección, análisis de datos o demostración) y el comando o archivo con que se comprueba. |
| **Rastreable** | Identificador estable (`RF` funcional, `RNF` no funcional), origen y evidencia con enlace. Las pruebas citadas llevan el nombre del archivo. |
**Autorrevisión del 2026-11-13** contra esas cuatro características: no se encontraron requerimientos sin criterio medible. Esto **no** sustituye la revisión de la integrante B (pendiente).

## 2. Estados usados
| Estado | Significado |
|---|---|
| **CUMPLIDO** | El criterio se comprobó con evidencia que existe y se puede repetir (se indica cuál). |
| **PARCIAL** | Se cumple en parte, o solo se comprobó una parte de lo que exige el criterio. |
| **NO CUMPLIDO** | Se midió y no alcanza el criterio. |
| **PENDIENTE** | Todavía no se ha ejecutado la comprobación. |
| **PROPUESTO** | Requerimiento nuevo de E1, con umbral fijado antes de tener datos suficientes; **requiere aprobación del equipo**. |
Ninguna cifra de esta tabla es una suposición: las que no se pudieron medir aparecen como PENDIENTE o PARCIAL y dicen por qué.
